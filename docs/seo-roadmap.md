# picthin SEO Roadmap

这个项目的 SEO 目标不是先追大词，而是从明确、低竞争、转化意图强的长尾词开始学习和验证。

## Phase 1: 上线基础

- 绑定正式域名，并确认全站只有一个规范域名。
- 构建前自动生成 `public/sitemap.xml` 和 `public/robots.txt`。
- 检查首页和博客页的 `title`、`description`、`canonical`、Open Graph、JSON-LD。
- 提交 Google Search Console、Bing Webmaster、百度站长。
- 确认 Cloudflare Pages 或托管平台启用 HTTPS，并把 HTTP 跳转到 HTTPS。
- 部署前运行 `npm run seo:check`，避免旧域名、缺失 canonical 或社交标签混进产物。

## Phase 2: 第一批关键词

优先围绕真实需求做页面，而不是只堆关键词。

- 图片压缩
- 在线压缩图片
- JPG 压缩
- PNG 压缩
- WebP 转 JPG
- PNG 转 WebP
- 图片格式转换
- 批量压缩图片
- 本地图片压缩
- 不上传图片压缩

## Phase 3: 内容计划

第一阶段建议每篇文章只解决一个问题。

- PNG、JPG、WebP、AVIF 怎么选（已完成）
- JPG 图片怎么压缩到指定大小（已完成）
- PNG 为什么压缩后还是很大（已完成，中英文独立页面）
- WebP 和 JPG 哪个更适合网页
- 图片压缩会不会影响清晰度（已完成，中英文独立页面）
- 图片本地处理与隐私验证（已完成，中英文独立页面）

## Phase 4: 每周复盘

- Search Console 里看展示量、点击量、平均排名。
- 找有展示但点击低的页面，优化标题和描述。
- 找排名 8-20 位的词，补内容、补内链。
- 记录每次改动日期，至少观察 2-4 周再判断效果。

## 常用命令

正式构建和检查：

```bash
VITE_SITE_URL=https://picthin.com npm run build
npm run seo:check
```


## 2026-10-10 实施与复查流程

- 中英文使用独立静态网址，语言由 URL 决定；首次偏好不匹配只提示切换。
- 当前 24 个公开页面各有中文和英文版本，共 48 个 URL；后台管理页不进入 sitemap。
- 每次新增指南，配置中文元数据、独立英文元数据/正文、路由，并让指南列表和相关文章提供可抓取链接。
- 教程样例标明原始文件大小和编码条件，示例结果不作为所有图片的性能保证。图片写明真实宽高并延迟加载。
- 构建后执行 `npm run seo:check`，核对静态正文、canonical、双向 hreflang、站内链接和 sitemap。
- 发布后核对生产部署的提交号，再检查新增 URL 的 HTTP 状态、语言、canonical 和资源。
- Google 的 URL 检查与站点地图、Bing 的网站地图与 URL 提交分别确认受理结果；请求已受理不等于已收录。

### 效果观察口径

1. 固定使用最近 28 个完整日期，记录报告的实际起止日期和数据更新时间；不要把不同时间窗口直接比较。
2. Search Console 按网页包含 `/en` 和不包含 `/en` 分别查看展示、点击、查询词；查询词明细可能不足以加总到总量。
3. Bing 单独记录，不与 Google 的排名或展示直接相加计算平均值。
4. Cloudflare Web Analytics 分别查看来源域、入口页、国家和设备；Visit 不代表已验证真人或去重用户。
5. 工具事件继续采用匿名聚合。`npm run analytics:report` 的凭据权限应按实际接口验证；遇到 401 先检查凭据是否过期，不要直接要求扩大权限。
6. 下载点击不代表文件成功保存，也不能直接除以访问量算独立用户转化率。当前工具事件不带语言或会话信息，不能关联某个搜索访客的完整行为。
7. 小样本期保留基线，2–4 周后再评估标题或内容变化；这份流程不是已建立的自动定时监控。
8. 实际后台数据和截图只保存在被 Git 忽略的本机目录，避免把账户统计发布到仓库。

### 仍需外部条件的事项

- 百度：已登录且站点已验证；2026-10-10 普通链接提交提示当日上限，sitemap 额度为 0，待额度恢复后继续。
- 真机覆盖：模拟手机检查不能替代低内存手机和 iOS Safari 的真实大图处理体验。
- 站外推广：准备材料可以本地完成；向第三方账号或社区发送内容需要明确的发布指示。


## 2026-10-10 第二轮技术与内容核对

- 保留现有 vite-react-ssg：公开页已生成正文，不需要为 SEO 迁移框架。
- 首页添加 WebSite 名称标记，公开页统一 og:site_name 为 PicThin；不承诺搜索引擎一定采用展示名称。
- JPEG/WebP 压缩后台线程使用打包版本的本站资源，按需加载，不依赖外部 CDN。首次下载失败可以重试。
- 新增中英文“如何检查图片没有上传”指南，提供公开样例、网络检查、断网测试、统计与反馈说明，以及元数据处理边界。博客、相关文章和关于页链接到指南。
- 旧格式对比文章的样例图片补齐真实宽高，预留加载空间。
- 发布检查解析所有 JSON-LD（包含带 data-rh 属性的标签），检查文章静态正文、图片尺寸、站点名称及后台线程资源，防止静态生成退化。
- FAQ 内容对用户仍有用，但 Google 已于 2026-05-07 停止 FAQ 富媒体结果；不以添加 FAQPage 换取折叠问答展示。
- 软件应用富媒体结果需要真实评分或评论等条件，不生成虚假评价；结构化数据不保证富媒体展示。
- 文章按实际问题组织，不设强制字数目标，不批量生成仅替换关键词的页面。外部推广材料可准备，发布仍需明确渠道和账号授权。

## 2026-10-10 用户场景搜索覆盖

- 复用并增强报名照片页，补充考试、入学与资格认证的不同要求，不新增仅替换人群名的重复页面。
- 新增求职图片附件指南：区分头像、证书与 PDF / Word 简历，覆盖单文件与合计上限、格式和尺寸错误。
- 新增证件扫描图片指南：区分资料页与人像照片，说明本地处理、文字检查、最低尺寸与正式提交边界，不承诺通过审核。
- 两篇新文均提供独立撰写的英文正文和元数据；复用 Article、canonical、hreflang 与 sitemap 生成流程。
- 工具列表及通用指定大小页提供六类场景入口：报名、求职、证件、透明商品素材、设计与网页格式、分享前元数据清理。已有相关内容保持原 URL。
- 场景文章按相关性互链。关键词字段不视为排名保证，主要依靠可索引正文、清楚的标题、真实操作步骤和内部链接。
- 观察新增 URL 的收录、展示、查询与实际访问；发布与 sitemap 更新不代表搜索引擎已经收录。
